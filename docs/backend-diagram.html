Trading System v1 / Backend Audit

Current Backend Runtime

Audited against the current repository on 2026-03-20. The active backend is mdengine, indengine, stratengine, and api_gateway, with tickserver as the staging feed. cmd/api is still a placeholder and is intentionally excluded from the runtime diagrams.

4 core services Redis streams + PubSub + snapshots + heartbeats SQLite WAL for candles, indicator snapshots, and signal journal 3 registered strategies in the live stratengine Dynamic FNO token subscription via cmd:subscribe_token

Runtime Services

  • mdengine owns live or staging ingest, 1s aggregation, TF building, raw tick PubSub, and market-state publishing.
  • indengine restores indicator state, consumes TF streams with consumer groups, runs Process and ProcessPeek, and checkpoints snapshots.
  • stratengine consumes closed 1m candles plus raw ticks, then handles signals, dynamic strikes, P&L, notifications, and order execution.
  • api_gateway is the real REST/WS serving layer, including replay buffers, gap backfill, active config persistence, and latency tracking.

Storage Contract

  • candles.db stores candles_1s, candles_tf, and indicator_snapshots.
  • signals.db is a separate append-only SQLite journal queried by the gateway.
  • historical.db belongs to offline tooling only and is produced by histdata.
  • Redis carries streams, latest keys, PubSub fan-out, snapshots, active config, strike info, P&L summary, and heartbeats.

Strategy Surface

  • The live stratengine registers NIFTY50_FNO, EMA3_HYBRID_FNO, and NIFTY50_FNO_SL.
  • Closed 1m TF candles drive entries and regular exits; raw ticks drive stop-loss checks, FNO LTP tracking, and strike resolution.
  • Dynamic strike automation uses SearchScrip, option-chain selection, and mid-session token subscription back into mdengine.

Serving Surface

  • /ws streams candles, indicators, signals, P&L, metrics, and strike updates.
  • REST covers candles, indicators, signals, P&L, strike info, config, missed-message replay, and health.
  • /healthz/services aggregates heartbeat:* keys from the four tracked services.
  • Gateway compatibility code still reads STRAT_IND_JOURNAL_PATH, but there is no current cmd/stratengine_ind binary.

Market data ownership

mdengine is the single source of live ticks and candles. It always publishes raw ticks to Redis for stop-loss and LTP tracking, even when candle aggregation is token-filtered.

Serving ownership

api_gateway is the actual backend API surface. It handles REST, WebSocket fan-out, replay-buffer gap backfill, active indicator config persistence, metrics broadcasts, and service-health aggregation.

Legacy cleanup

The previous stratengine_ind split is no longer present as a binary. The current runtime uses one stratengine process with three registered strategies and one shared order executor.

Candle database split

candles.db is the shared market-data SQLite store. It carries both raw 1s candles and finalized TF candles, plus indicator_snapshots for cold restore.

Signal database split

signals.db is separate and append-only. stratengine writes it, and api_gateway reads it directly for /api/signals.

Gateway config loop

When the frontend updates /api/indicators/active, the gateway persists gateway:active_config and publishes config:indicators so indengine can reload.

Entry vs tick path

Entries and regular exits come from closed 1m TF candles. Raw ticks are used for live stop-loss evaluation, FNO LTP updates, and dynamic strike resolution.

Dynamic strikes

Resolved CE/PE tokens are written back into Redis and republished through cmd:subscribe_token, allowing mdengine to expand the live WS subscription mid-session.

Daily hygiene

Startup stale-position cleanup and 15:30 IST auto-exit both inject synthetic exits through the strategy engine, so order execution and journaling still use the same normal signal path.

Staging parity

Staging keeps the same Redis, SQLite, indicator, strategy, and gateway flow. Only the market-data source changes from Angel One WS to tickserver.

Production-only behavior

Production mdengine adds market-hours gating, close detection, pre-open session handling, and live Angel authentication. Production stratengine can place real orders when enabled.

Offline scope

histdata builds a separate historical.db; replay and strategy backtests operate on that dataset rather than the live runtime databases.
